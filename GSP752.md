# GSP752 – Managing Terraform State

## Known lab bugs (read first)

1. There is only one checkpoint, worth all 100 points, and it sits in the middle of Task 1. Click it after Block 3 (refresh), before the clean-up block. If you run the clean-up first, the bucket is gone and the check says "Please modify main.tf to create a storage bucket with project_id". Rerun Blocks 1–3 and check again. Task 2 isn't scored.
2. Big pastes get garbled in Cloud Shell. Paste one block at a time and wait for the prompt to come back before pasting the next.
3. After installing Terraform, the same terminal can keep showing the "install terraform" message even though Terraform is installed. Open a new Cloud Shell tab (+ next to the cloudshell tab) or run `hash -r`.
4. The region changes per lab instance. Find it in the main.tf sample in Task 1 (the `region = "..."` line) and set it in Setup.
5. The lab text about the Docker repo is out of date. The `sed` version fix finds nothing to change, and the provider host is already a Linux socket, not `npipe`. Both are harmless. The blocks below skip them.
6. The lab's "minimal" docker.tf shows `image = "nginx:latest"`, but the real imported value is a sha256 image ID. If you type nginx:latest, Terraform replaces the container instead of just updating it. Block 4 of Task 2 uses the real ID.
7. The checker lags. If a check shows 0 right after a successful step, wait 30–60 seconds and click again.

## Install Terraform – follow the lab

Do the lab's "Prerequisite > Install Terraform" step exactly as written: click the copy button on its code block, paste it into Cloud Shell, and run it. Then run the lab's `terraform --version`.

If it still prints "Follow the instructions ... to install terraform", open a new Cloud Shell tab or run:

```bash
hash -r

```

## Task 1 – Work with backends

Block 1 – main.tf with a local backend, then apply:

```bash
cd ~
cat > main.tf <<EOF
terraform {
  backend "local" {
    path = "terraform/state/terraform.tfstate"
  }
}

provider "google" {
  project = "`cat ~/project`"
  region  = "`cat ~/region`"
}

resource "google_storage_bucket" "test-bucket-for-state" {
  name                        = "`cat ~/project`"
  location                    = "US"
  uniform_bucket_level_access = true
}
EOF
terraform init
terraform apply -auto-approve
terraform show
```

Block 2 – switch to the Cloud Storage backend and migrate the state:

```bash
cd ~
sed -i 's|backend "local" {|backend "gcs" {|' main.tf
sed -i "s|path = \"terraform/state/terraform.tfstate\"|bucket = \"`cat ~/project`\"\n    prefix = \"terraform/state\"|" main.tf
head -6 main.tf
terraform init -migrate-state -force-copy
gcloud storage ls -r gs://`cat ~/project`
```

You should see `terraform/state/default.tfstate` in the bucket.

Block 3 – add the label and refresh the state (same as the lab's Console steps):

```bash
cd ~
gcloud storage buckets update gs://`cat ~/project` --update-labels=key=value
terraform refresh
terraform show | grep -A3 labels
```

You should see `"key" = "value"` under labels.

Block 4 – clean up (revert to local, add force_destroy, destroy):

```bash

terraform {

  }
}

provider "google" {

EOF
terraform init -migrate-state -force-copy

terraform destroy -auto-approve
```

## Task 2 – Import a Terraform configuration

Block 1 – create the Docker container:

```bash
docker run --name hashicorp-learn --detach --publish 8080:80 nginx:latest
docker ps
```

Optional: Web Preview > Preview on port 8080 shows the NGINX welcome page.

Block 2 – clone the repo and init:

```bash
cd ~
rm -rf learn-terraform-import
git clone https://github.com/hashicorp/learn-terraform-import.git
cd learn-terraform-import
terraform init -upgrade
```

Block 3 – empty resource, then import the container:

```bash
cd ~/learn-terraform-import
echo 'resource "docker_container" "web" {}' > docker.tf
terraform import docker_container.web `docker inspect -f {{.ID}} hashicorp-learn`
terraform show
```

Block 4 – write the configuration to match the imported container:

```bash
cd ~/learn-terraform-import
cat > docker.tf <<EOF
resource "docker_container" "web" {
  image = "`docker inspect -f {{.Image}} hashicorp-learn`"
  name  = "hashicorp-learn"
  ports {
    external = 8080
    internal = 80
    ip       = "0.0.0.0"
    protocol = "tcp"
  }
}
EOF
cat docker.tf
terraform plan
terraform apply -auto-approve
```

The plan should only show an update (attach, logs, must_run, start), not a replace.

Block 5 – add the image resource:

```bash
cd ~/learn-terraform-import
cat >> docker.tf <<'EOF'

resource "docker_image" "nginx" {
  name = "nginx:latest"
}
EOF
terraform apply -auto-approve
```

Block 6 – point the container at the image resource:

```bash
cd ~/learn-terraform-import
sed -i 's|^  image = ".*"|  image = docker_image.nginx.image_id|' docker.tf
cat docker.tf
terraform apply -auto-approve
```

This should show no changes.

Block 7 – manage the container with Terraform (port 8080 to 8081):

```bash
cd ~/learn-terraform-import
sed -i 's/external = 8080/external = 8081/' docker.tf
terraform apply -auto-approve
docker ps
```

The container ID changes because Terraform replaced it.

Block 8 – destroy:

```bash
cd ~/learn-terraform-import
terraform destroy -auto-approve
docker ps --filter "name=hashicorp-learn"
```

The list should be empty.
